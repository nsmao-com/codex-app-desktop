# Codex 模型元数据与文件修改列表

## CLI 警告与持久提示（1.5.8）

输入框和目标编辑区下方的警告图标会保留 Codex 非致命提示。悬停查看摘要，点击展开
原文、详情、配置文件位置与行列号；相同提示不重复弹窗，最多保留最近 32 项。
提示保存在当前应用的本机存储中，刷新界面不会丢失；常见凭据字段在存储前脱敏。
可复制诊断、进入配置设置，或在没有运行、排队、审批及历史加载任务时重新检查。
重新检查会重启当前 Codex 连接并重新收集提示，不会删除用户配置。真正的连接或执行
失败仍使用错误通知，不会被降级或隐藏。

警告来源不能只凭标题判断：

- `configWarning` 使用 `summary`、`details`、`path`、`range`；行列号由 CLI 提供且从 1 开始。
- `deprecationNotice` 使用 `summary` / `details`，可能是软件调用了旧接口，并不表示用户配置错误。
- 普通 `warning` 和 `guardianWarning` 使用 `message`；线程级提醒只显示在对应会话。
- Windows 可写目录警告提供目录样本、额外数量及扫描失败状态，也需要显示这些信息。

本轮真实复现的警告为：`Full-history hydration is deprecated for paginated threads`。
原因是旧版 Nice Codex 使用全量历史读取 / 恢复接口，不是用户的 config.toml 有问题。
1.5.8 对已核对协议的 Codex CLI 0.153.4 及更新版本使用 metadata-only read、
`excludeTurns` resume 和 `thread/turns/list`：最新一页读取 full items，旧回合先读取轻量
信息与分页游标，向前翻页时再读取内容。存活检查仅读取最近一轮的元数据。
旧 CLI 保留原有兼容路径；分页失败会提示错误，不会伪装为空历史。缓存继续遵守既有
内存预算，并防止重复游标导致无限读取。

若 CLI 明确报告不支持的配置项：先根据提示定位文件并备份，再按原文修改对应项。
如果未提供路径，界面会明确说明；可检查 CODEX_HOME/config.toml、项目 .codex/config.toml
及启动参数，不应直接删除整个配置文件或替换用户的密钥、模型商设置。

### 1.5.8 验证范围

- 真实默认全局 0.153.4 + gpt-6-astra 请求、重新连接和历史恢复后，不再产生上述弃用提示。
- 临时缩小 dev 页大小验证 20 轮真实历史的 8 / 8 / 4 分页，回合无重复且旧工具内容完整；发布默认已恢复为每页 24 轮。
- 归档验证会话恢复后，原生文件新增 / 删除事件和差异详情仍正确。
- 协议样例验证配置路径、1-based 行列号、Windows 权限提示、100 次重复去重、32 项上限、损坏存储容错及常见凭据脱敏。
- 原生 WebView2 验证 tooltip、详情定位、复制、设置跳转、Esc 焦点恢复、刷新保留、窄窗口、英文 / 深色主题、目标编辑模式和空闲重新检查。
- 实际回合运行时重新检查被禁用；普通错误通知仍可见。TypeScript、已有 Go 测试、go vet 和 diff 检查通过。

这些是定向回归，不是所有模型商的全量请求测试，也不是低内存实机的长期压力保证。

## Astra 元数据兼容

模型能被选择、API 请求能成功，不代表本地 Codex CLI 已有对应元数据。
`Model metadata for gpt-6-astra not found` 来自 CLI，不是模型选择器。

Nice Codex 启动 app-server 时读取该 CLI 的有效模型目录：

- 已有 `gpt-6-astra`：保持原生或用户自定义条目，不覆盖。
- 缺少 Astra：保留所有现有模型，只补入 `internal/codex/astra_model.json`。
- 目录读取失败、格式无效或 CLI 太旧：不替换目录、不阻断其他模型，输出兼容诊断，需更新官方 CLI。

补充数据通过本次 app-server 的 `-c model_catalog_json=...` 加载；临时目录随进程结束清理，不修改 `~/.codex/config.toml`、模型缓存、密钥或服务商。
目录读取限制为 8 秒、8 MiB，避免异常 CLI 长时间阻塞或无限占用内存。

### 数据来源与更新规则

`astra_model.json` 是从官方 `@openai/codex@0.153.4` 的
`codex debug models --bundled` 中完整提取的 Astra 条目，提取日期为 2026-09-05。
该包标注 Apache-2.0 许可证，许可证正文见 [Apache-2.0](licenses/Apache-2.0.txt)。此许可证说明针对来自 OpenAI Codex 的模型快照，不改变本项目其他代码的许可。
没有复制其他模型参数，也没有把 API 的最大上下文直接当作 CLI 默认值。
保留官方 instructions、工具类型和上下文策略作为同一份快照。
未来更新该快照时，应重新从明确版本的官方包提取并验证；不要手工伪造参数。

## Windows CLI 安装不完整

仅 `codex --version` 成功不能证明工具能工作。已知 0.149+ 官方 Windows bundle
还需要 `bin/codex-code-mode-host.exe` 和 `codex-resources` 中的沙箱辅助程序。
Nice Codex 会对该版本及布局进行完整性检查，并在设置页保留具体缺失诊断。

建议修复步骤：

1. 等待正在执行的 Codex 任务结束。
2. 在「设置 → CLI 工具」重新安装/更新 Codex；该操作不会删除会话或服务商配置。
3. Windows 必要时使用 `pnpm add -g --allow-build=@openai/codex --config.modules-cache-max-age=52560000 @openai/codex@latest`；其他系统可省略缓存保留参数。
4. 确认没有旧的 pnpm 安装任务仍在运行，避免多个安装任务同时修改全局目录。
5. 重新连接 Nice Codex。自定义 `CODEX_BIN` 时，应指向完整官方安装中的程序，不要只复制单个 EXE。

Windows 上，仍在运行的旧 CLI 可能锁住 EXE。pnpm 清理旧包时可能先删掉辅助文件，
随后卡在无法删除的 EXE；此时反复点击安装不会解决问题。上面的参数仅对本次安装延长
旧包缓存保留期（单位为分钟），不修改永久配置，不结束会话。旧包会占用磁盘空间，
应在所有 CLI 退出后再安排缓存清理，不要在工作期间强删。
Nice Codex 的 pnpm 安装入口已使用同样的保留参数，并阻止不同模型商同时进行全局安装。
该互斥只覆盖当前软件进程；外部 CLI 切换器、终端或另一个 Nice Codex 实例也在安装时，
应先等待其完成或关闭其自动安装功能，再进行修复。

如果辅助程序确实存在但仍提示找不到路径，检查完整路径是否过长；部分原生子进程启动路径仍受 Windows 路径长度限制。
不要删除 `~/.codex`、注销 WSL 或关闭安全保护来处理这个问题。

## 回合末尾的文件修改

末尾列表依赖原生 `fileChange` 和 `turn/diff/updated`，不是根据模型名称开关。
通过原生 `apply_patch` 完成的修改可获得这些事件；通过外部 MCP、脚本或其他进程改文件，不保证产生原生补丁事件。
不应把整个工作区当前 Git 状态冒充该回合的修改清单，因为其中可能有用户或其他会话的改动。

展示层将同一工作区内的绝对/相对路径统一后去重，保留不同目录的同名文件。
原生新增/删除事件中的文件内容会转换为统一 diff，让增删行数、差异详情和重新打开历史保持一致。
失败或拒绝的补丁不计入末尾已修改文件列表。

历史加载和工作区切换的调度屏障使用响应式状态；加载完成后即解除忙碌显示，
不会因为已结束的历史读取导致下一条消息一直停在排队状态。
